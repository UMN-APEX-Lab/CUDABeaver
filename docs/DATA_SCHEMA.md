# Data schema & family semantics

## Instance layout

Each of the 203 instances lives in `data/<instance_id>/` where
`instance_id = <base_stem>__<error_category>__<hash8>`:

```
instance.json    provenance + category + hashes
input.json       build_command / test_command / task_id (= instance_id)
prompt.txt       repair prompt shown to the fixer
broken_start.*   the degenerated kernel the fixer must repair (.cu/.h/.py)
reference.*      reference implementation (see per-family semantics below)
testbench/       task-specific build+test harness
```

`benchmark/task_list.json` is the canonical index: 203 entries keyed by the
full instance id. **Do not key by base stem** — 18 stems have two instances
(different broken starts of the same underlying task); `task_id_base` is
provided for grouping only. The flat dirs `data/{input,prompts,testbench,
references}/` are instance-id-keyed symlinks generated by
`scripts/prepare_benchmark.sh`.

## Per-family reference semantics

| family | reference is | pass criterion | perf baseline |
|---|---|---|---|
| cuda_*, cublas_*, cusolver_*, cusparse_*, cufft_<n> | compilable program (`reference.cu`) | testbench exit 0 | `benchmark/references/` spec, NVTX `bench_region` kernel timing |
| kernelbench_* | pure-PyTorch model (`problem.py`); `reference.cu`-stored solutions are Python | `kernelbench.eval` correctness | kernelbench eval runtime_stats |
| cutlass_*, cufft_samples_*, flashattention_*, layernorm_* (applied) | upstream example restored (`reference.cu`) | make-driven test | self-timed inside the test binary (per-size speedups, geomean) |
| cudabench_* | **no compilable reference** — oracle is `test/compare_output.py` | sanitizer + output comparison | correctness-only (no speedup defined) |
| thunderkittens_* | TK kernel (`reference.cu`) | make-driven test | self-timed; **requires sm_90a** (see below) |

Note on CUTLASS-family references: `reference.cu` is the restored upstream
CUTLASS example; the build pulls headers from the bundled
`data/_external/cutlass/` snapshot via each testbench's `reference_sources/`
(relative) symlink. The reference is what the broken start was degenerated
from — it is the repair target's semantics, not necessarily the fastest
possible implementation on any given GPU. For the applied families
(cutlass/flashattention/layernorm) `reference.cu` is a PROVENANCE artifact,
not a drop-in candidate: it is the full upstream example (cutlass) or relies
on library-internal headers (flash_attn) that the anti-cheat build
deliberately withholds from candidates, which must be self-contained. The
family fixtures therefore validate the toolchain with a perf_broken
broken_start (compiles + passes correctness by construction).

## Architecture adaptation (important)

The corpus was authored on Blackwell (RTX PRO 6000, sm_120), and task
commands embed two authoring-machine constants that the harness rewrites **at
execution time** to the machine actually running (`harness/compiler.py::
adapt_gpu_arch_cmd`, override with `CUDA_DEBUGGER_GPU_ARCH`):

- `set_gpu_arch(['Blackwell'])` in kernelbench commands → detected family
  (Hopper/Blackwell/Ada/Ampere);
- `make GPU=RTX5070` in ThunderKittens commands → `GPU=H100` on Hopper.

ThunderKittens caveat: the 4 TK instances use wgmma-path kernels that exist
only in TK's sm_90a (Hopper) branch. On Hopper they build and run; on
Blackwell they are architecture-gated (build fails in the TK library, and
their reference timing is skipped as `incompatible_arch`) — they are counted
in denominators, bounded at <0.7pp on pass@5 (see paper appendix).

## Timing baselines

`benchmark/references/` ships one timing spec per timeable instance (168);
`benchmark/references_cache/<gpu_signature>/` ships measured baselines for
two architectures (Blackwell sm_120 / CUDA 13.0, and H200 sm_90 / CUDA 12.9).
`analysis/p_sweep.py` re-scores gated pass@5 at 9 thresholds offline.
